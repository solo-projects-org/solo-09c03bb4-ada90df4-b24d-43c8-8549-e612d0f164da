# 分期分流核验（Flask + SQLite）

试验开轮时固定「各期应到人数」和「每人独立分到 B 组的概率」，随后按期上传含
用户编号与实际组别的 CSV。服务把每期实际数据与计划对照，算出截至当期的
B 组累计人数分布，并标出最早出现分流异常（p 值 ≤ 0.05 / 计划期数）的期次。

## 运行

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据持久化在 compose named volume `split-data` 中（容器内 `/data/split.sqlite3`）。
需要换库时设置环境变量 `DIV_DB`，要固定 Flask 会话密钥时设置 `SECRET_KEY`。

去标识密钥默认写在数据库同目录的 `deid.key`（即 named volume 内、SQLite 之外；
compose 中显式设为 `/data/deid.key`），也可用 `DEID_KEY_FILE` 指定路径。
**密钥与数据库要分开备份**：只有库没有密钥时，已生效的去标识轮次会暂停接收
新报送，避免退回收原编号。

本地不装 Docker 时也可以直接跑：

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
DIV_DB=data/split.sqlite3 .venv/bin/gunicorn --bind 0.0.0.0:8000 --workers 2 --threads 4 app:app
```

`data/` 目录会由容器启动脚本 / `app.bootstrap()` 自动创建。

## 使用流程

1. **计划设置**（`/plan`）：选择 1–8 期，逐期填写应到人数与 B 组概率（0<p<1，
   最多 12 位小数），各期人数合计必须为 1000。计划在第一次上传后锁定；如需
   换比例，先在计划页输入 `RESET` 清空本轮明细（计划保留、可重新调整）。
2. **按期上传**（`/period/<n>`）：CSV 至少包含「用户编号」和「组别」两列，
   列名可用 `user_id`/`user`/`用户编号` 与 `group`/`组别`/`实际组别` 等，
   组别取值只能是 `A`/`B`。人数必须与该期计划一致。
3. **查看总览**（`/`）：每期的实收人数、本期 B 组人数、累计 B 组人数、
   期望累计 B、p 值、阈值与状态；页面顶部显示最早触发异常的期次。
4. **本轮去标识**（`/` 的「本轮去标识」面板）：名单未收齐也可启用。按钮会显示
   「未生效 / 已生效」；启用后业务表只保存不可逆代号，后续报送照常。具体规则
   见下文。
5. **查看某期分布**（`/period/<n>`）：截至该期的累计 B 分布、分位数、
   直方图与上下尾概率明细。另提供 `GET /api/period/<n>` 的 JSON 视图。

## 规则与算法

* **每期独立、每人只计一次**：每期的分组视为参数为该期计划概率的独立二项
  分布；用户编号是全轮主键，重复出现在其他期会被拒收。
* **到齐才核验**：只核验从第 1 期起连续到齐的期次。缺报时先接收后续期，
  缺口补齐后自动按计划顺序把能连续核验的期次全部补算。
* **累计分布**：截至第 k 期的 B 组累计人数分布 = 第 1..k 期二项分布的卷积。
  每次核验都用截至当期各期的计划概率重新计算，而不是沿用上一期的分布。
* **p 值**：`p = min(1, 2 × min(P(X ≤ 实测), P(X ≥ 实测)))`，两个尾概率都包含
  实测值。全部用 `decimal.Decimal`（80 位精度）计算，避免浮点误差；页面上的
  极小 p 值用科学计数法展示。
* **异常判定**：`p ≤ 0.05 / 计划期数`（Bonferroni 阈值）即标记该期异常，
  并取最早满足条件的期次作为「最早触发分流异常的期次」。
* **重传**：同一期再次上传与已接收明细完全相同的内容（逐行 `用户编号+组别`
  的 SHA-256）只回执「已接收」，不新增记录、不重复计数；内容有任何变化则整份
  拒收。拒收/失败的上传不会影响已收明细和已有核验结果。
* **并发**：写操作使用 SQLite `BEGIN IMMEDIATE` 事务串行化，`uploads` 以期次
  为主键。并发补报同一期时只有一份能落库，其余得到「相同明细已接收」或
  「拒收」；每期结果至多一行。

## 本轮去标识

* **入口与状态**：总览页的「本轮去标识」面板显示「未生效 / 已生效」（含生效
  时间与已转换条数），未生效时提供「启用本轮去标识」按钮。无需等名单收齐。
* **不可逆代号**：启用时用 HMAC-SHA256（密钥在 `deid.key`，不在库里）把
  `(轮次序号, 用户编号)` 映射为 `deid-<32 位十六进制>`。数据库中不再出现原
  编号；没有密钥无法从代号反推。`uploads` 的内容摘要也会改成带密钥的 MAC，
  避免小编号空间被枚举。
* **覆盖范围**：启用事务内一次性重写 `assignments` 存量；处理中接收的名单与
  之后报送的 CSV 仍按原编号填写，入库时即时换算成代号。任何一步失败整体回滚，
  本轮继续按原编号报送。
* **轮内固定、换轮不同**：同一编号在同一轮始终得到同一代号（跨期查重、同份
  重传的判断不受影响）；`round_meta.round_serial` 参与 MAC，重置后的新一轮
  会对同一编号得到不同代号。
* **重复启用**：已生效的一轮再次提交只回执当前状态，不改数据、不改生效时间。
* **重传语义不变**：同一期重传原 CSV（原编号、同组别）仍只回执「已接收」；
  内容变化仍整份拒收；跨期重复编号仍按「每人全程只计一次」拒收（提示里显示
  数据组发来的原编号）。停用去标识时写入的旧摘要会在切换时同步换算。
* **核验口径不变**：`results` 与累计核验只依赖期次、人数与 B 组计数，切换
  前后以及补齐缺期后的累计核验都与未切换时一致（有对照测试）。
* **失败与重启**：切换失败（如事务繁忙/密钥写失败）不留半成品，继续按原编号
  报送；已生效状态、密钥与代号都持久化，重启后继续按代号接收。若密钥缺失或
  与本轮不匹配，页面会告警并暂停接收新报送，而不是退回原编号。
* **重置**：清空本轮数据、`round_serial` 加一并清除去标识状态；旧一轮未完成
  的切换请求因序号不匹配被拒，不会作用到新一轮。新一轮需单独启用。
* **旧库升级**：启动时自动为既有 SQLite 补 `round_meta.round_serial` 与
  `deid_state` 表，已有计划、上传和核验结果原样保留。

## 测试

```bash
.venv/bin/python -m pytest tests -q
```

测试覆盖：计划校验（合计 1000、期数上限、概率范围）、人数不符/组别非法/
文件内重复/跨期重复、乱序上传与缺口补齐、每期使用各自计划概率、相同重传
只计一次、内容变化拒收后保留结果、Bonferroni 阈值与最早异常期、并发相同/冲突
上传只留一份、API 与页面渲染；去标识覆盖存量转换、未收齐时启用、启用后跨期
报送、轮内固定/换轮不同、重复启用只回状态、重传与跨期重号、切换失败与重启、
旧库升级、切换与上报并发交错，以及切换与未切换的累计核验结果对照。

`examples/generate.py` 可以生成三期的演示 CSV（第 2 期故意偏向 B 组）：

```bash
python examples/generate.py examples/data
```
